- 时间：2026-08-20

### 功能目标

### 小程序请求层修改

#### `frontend/miniprogram/services/api.js`

新增：

```javascript
markAlertRead(alertId)
```

该方法向 `/alerts/{alertId}/read` 发送 PATCH 请求，并复用自动登录、Bearer Token、401处理和统一 Promise 返回逻辑。

### 小程序每日记录修改

#### `frontend/miniprogram/pages/daily/index.js`

1. 将原本的异常提醒字符串数组改为结构化对象，字段包括：
   - `id`：后端提醒 ID。
   - `title`：提醒标题。
   - `content`：提醒正文。
   - `riskLevel`：`low`、`medium` 或 `high`。
   - `isRead`：是否已读。
2. `applyDailyPayload()` 不再丢弃提醒 ID 和风险信息，而是将后端的 `risk_level`、`level`、`is_read` 映射到页面状态。

4. 新增 `markAlertRead(event)`：
   - 根据点击项的索引找到提醒。
   - 已读、无效或本地演示提醒不重复发送请求。
   - 调用后端成功后只更新对应数组项的 `isRead`，避免整页刷新。
   - 成功显示“已标记为已读”，失败显示后端错误。

- 未读且已连接后端时显示“点击标记已读”。

#### `frontend/miniprogram/pages/daily/index.wxss`

#### `backend/app/api/daily/resources.py`

```text

}
```

处理流程：

1. 要求提供 `date`。

3. 为 OCR 状态增加 `ocrProgressStyle`：
   - 初始状态为 `width: 0%;`；
   - 选择新报告时重置为 `width: 0%;`；
   - 启动识别时设置为 `width: 8%;`；
   - 轮询识别进度时随接口返回值更新。
4. OCR 动态宽度在生成样式前限制在 `0` 到 `100` 之间，避免异常接口值造成进度条溢出。
5. WXML 改为绑定完整样式字符串：

```wxml
style="{{item.progressStyle}}"
style="{{records.ocrProgressStyle}}"
```

6. 保留原有 `progress` 和 `ocrProgress` 数值字段，页面百分比文字、业务判断和后续逻辑不受影响。

## 迭代 20：修复健康趋势 ECharts 首次进入不渲染

- 时间：2026-08-22 16:04（Asia/Shanghai）
- 对话背景：项目在微信开发者工具中运行后，用户反馈每日记录页的“健康趋势”没有显示；上一轮先完成原因定位，本轮按定位结果实施修复并重新加载项目。
- 变更类型：小程序前端生命周期修复，不涉及后端结构、数据库迁移或 AI 算法。

### 问题现象

每日记录页默认打开“概览”面板，点击“趋势”后可以看到趋势区域和 7 天/30 天切换按钮，但 ECharts 折线图没有完成渲染。

### 根本原因

1. 页面初始 `activePanel` 为 `overview`。
2. 趋势区域使用 `wx:if="{{activePanel === 'trend'}}"`，所以页面 `onReady()` 执行时 `ec-canvas` 尚未创建。
3. 原 `onReady()` 此时调用 `initTrendChart()`，`selectComponent("#vitals-trend-chart")` 返回空，方法直接结束。
4. 原 `switchPanel()` 只更新 `activePanel`，点击“趋势”后没有再次调用图表初始化。
5. 因此接口数据虽然已经加载到 `trendPoints`，但没有 ECharts 实例接收 `setOption()`，最终表现为图表空白。

### 具体修改

1. `initTrendChart()` 增加两个前置保护：
   - 仅在当前面板确实为 `trend` 时初始化；
   - 已存在 `trendChart` 实例时不重复初始化。
2. `switchPanel()` 先获取目标面板，点击当前面板时直接返回，减少无效渲染。
3. 面板切换前释放已有 ECharts 实例并清空全局引用，防止 `wx:if` 销毁 Canvas 后遗留旧实例。
4. 每次切换面板时将 `chartReady` 重置为 `false`，使加载/降级状态与真实图表状态一致。
5. 切换到 `trend` 后，在 `setData` 完成回调中调用 `wx.nextTick()`；等待 WXML 和自定义组件挂载完成后，再执行 `initTrendChart()`。
6. 数据请求与原 7 天/30 天范围切换逻辑保持不变；数据先返回或 Canvas 先初始化两种顺序均会调用 `renderTrendChart()`。
