# 三高健康管理小程序项目交接文档

## 1. 交接结论

本项目目前是一套可在 Windows、Docker Desktop 和微信开发者工具中运行的前后端分离微信小程序。用户端主要业务流程、后端 REST API、MySQL 数据库迁移、Redis 限流、版本化隐私授权、数据导出和授权撤回均已实现并完成本地验证。

当前版本适合作为继续开发、课程验收、体验版联调和生产化改造的代码基线，但不能在没有正式微信权限、生产密钥、HTTPS 域名、真实 AI/OCR 服务和合规审查的情况下直接发布上线。

## 3. 技术栈

### 小程序前端

- 微信小程序原生 WXML、WXSS、JavaScript；
- 微信小程序登录、请求、上传、文件系统、分享和弹窗 API；
- ECharts 微信小程序组件，用于健康趋势；
- `miniprogram-automator`，用于微信开发者工具自动化验收。

### 后端与数据

- Python 3.12、Flask、Flask-RESTful；
- SQLAlchemy、Flask-Migrate、Alembic；
- MySQL 8.4；
- Redis 与 Flask-Limiter；
- Gunicorn；
- Pytest；
- Docker Compose。

### 外部能力边界

- 微信正式身份交换代码已经实现，生产使用 `code2Session`；
- OCR、预测、大模型和知识库服务已经预留后端边界或演示流程，真实算法、服务地址、鉴权和质量由 AI 负责人继续完成；
- 管理员后端 API 已保留，普通用户小程序不包含隐藏管理员入口。生产管理员端应使用独立受控 Web 后台、管理小程序或企业微信应用。

## 4. 已完成的用户功能

### 每日记录

- 日期和日历切换；
- 血压、空腹/餐后血糖等健康指标录入；
- 早餐、午餐、晚餐和加餐记录；
- 每日待办与完成状态；
- 健康异常提醒；
- 7 天/30 天健康趋势切换和 ECharts 展示；
- 健康指标预测结果展示。

### 体检报告

- 图片/PDF 上传接口与前端流程；
- 识别任务、进度查询和报告历史；
- 报告详情和指标展示；
- 指标人工纠错；
- 报告确认、删除和重新识别；
- 后端报告审核及批量审核 API。

### AI 页面

- 快捷问题；
- 今日健康上下文；
- 会话列表、消息和来源展示；
- 已有前后端数据契约，真实大模型/OCR/预测结果由 AI 负责人联调替换。

### 我的与个人信息权利

- 个人资料、头像、健康档案和提醒设置；
- 微信登录、Token 版本和退出后失效；
- 管理员停用账号后旧 Token 立即失效；
- 用户协议、隐私政策和敏感健康数据授权按版本记录；
- 当前版本升级后要求用户重新确认；
- 个人数据 JSON 副本生成、写入小程序目录与文件分享；
- 撤回健康数据授权；
- 撤回后每日记录、趋势、报告和 AI 健康上下文立即返回 403；
- 数据导出、协议查看和重新授权仍然可用；
- 重新授权后恢复健康功能。

## 5. 后端与管理员能力

后端已实现普通用户数据隔离和 `/admin/*` 角色校验。管理员 API 覆盖：

- 仪表盘；
- 用户列表、详情、资料维护和停用；
- 报告审核及批量审核；
- 食物营养数据增删改查及批量删除；
- 公告增删改查及批量发布/转草稿。

没有在普通用户微信小程序中创建管理员页面，这是有意的安全边界。是否显示入口不能替代后端权限校验。后续若制作管理员界面，应独立部署并增加 MFA、细粒度 RBAC 和操作审计。

## 6. 本地启动方式

### 必需软件

- Windows 10/11；
- Docker Desktop，WSL 2/虚拟化可用；
- 微信开发者工具；
- 仅在运行自动化测试时需要 Node.js。

### 启动后端

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\启动开发环境.ps1
```

脚本会构建并启动 MySQL、Redis 和后端，自动执行数据库迁移。不要在容器刚启动时并发手工执行 `flask db upgrade`。

健康检查：

```text
http://127.0.0.1:5000/api/v1/health
```

期望返回业务码 `0`、状态 `ready`。

停止但保留数据：

```powershell
powershell -ExecutionPolicy Bypass -File .\停止开发环境.ps1
```

禁止把 `docker compose down -v` 当作普通停止命令；它会删除 MySQL、Redis 和上传持久卷。

### 微信开发者工具

1. 导入解压后的项目根目录，不要只导入 `frontend/miniprogram`。
2. `project.config.json` 已声明 `miniprogramRoot=frontend/miniprogram/`。
3. 开发环境接口默认是 `http://127.0.0.1:5000/api/v1`。
4. 启动 Docker 后端后点击编译。
5. 真机不能访问电脑自身的 `127.0.0.1`，需要 HTTPS 测试域名或可访问的联调地址。

没有原 AppID 成员权限不影响查看和修改源码，也不影响使用测试号进行大部分本地开发；但会影响原 AppID 下的正式登录联调、体验版上传、真机权限验证、审核和发布。

## 7. 测试与当前验证基线

### 后端

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest -q
```

最后一次完整结果：`36 passed`。

若新电脑没有本机 Python 虚拟环境，可在 Docker 容器中安装测试依赖后运行，或创建新的 `.venv`。交付包不包含旧电脑虚拟环境。

### 微信开发者工具自动化

```powershell
npm install
& "微信开发者工具安装目录\cli.bat" auto --project "解压后的项目根目录" --auto-port 9420 --trust-project
npm run test:miniprogram
```

最后一次真实后端验证通过：授权页、隐私政策、授权写入、每日记录、AI、我的、数据导出、撤回授权、重新授权恢复。自动化只操作微信开发者工具，不使用浏览器预览。

## 8. 配置与密钥说明

- `.env.example` 只有示例值，正式部署必须复制为 `.env` 并替换全部占位符；
- `.env`、微信 AppSecret、管理员真实密码和生产 Token 不进入交付包；
- 正式环境必须使用 `APP_ENV=production`、HTTPS、独立数据库账号、强随机 `SECRET_KEY`、管理员密码哈希、Redis 限流、`code2Session` 和 `HEALTH_CONSENT_REQUIRED=true`；
- `trial`、`release` API 地址目前为空，上体验版/正式版前必须配置 HTTPS 源站；
- 微信公众平台还要配置 `request`、`uploadFile` 等合法域名；
- 当前 AppID 写在 `project.config.json`，接收人没有该项目成员权限时应改用测试号或自己的 AppID。

## 9. 数据、备份和交付包边界

源码交付包不包含：

- `.env` 和任何正式凭证；
- `project.private.config.json`；
- Python `.venv`、Node `node_modules`、缓存；
- 本机 SQLite、数据库备份、上传文件；
- Docker MySQL/Redis/上传数据卷。

因此在另一台电脑首次启动时会创建新的数据库和演示数据，不会自动携带当前电脑的用户数据。如果交接真实数据，必须单独进行 MySQL 加密备份、传输、恢复和权限审计。

## 11. 推荐接手顺序

1. 解压后先阅读本文件、`README.md`、`docs/上线部署清单.md` 和 `docs/迭代记录.md` 最近三次迭代。
2. 启动 Docker，确认健康检查 ready。
3. 在微信开发者工具编译并手动走一次授权、每日记录、趋势、报告和数据导出。
4. 运行后端36项测试和小程序自动化。
5. 根据人员分工锁定 AppID/AppSecret、AI接口、对象存储、HTTPS域名和合规负责人。
6. 完成剩余代码后先发体验版，经过真机、多用户、安全和恢复演练再申请发布。

## 12. 重要注意事项

- 本项目提供健康管理参考，不应声称替代医生诊断或紧急医疗服务。
- 不要把管理员功能通过隐藏按钮塞入普通用户小程序。
- 不要将 AppSecret、数据库密码或真实用户健康数据提交到源码或压缩包。
- 不要恢复网页预览作为功能验收依据；当前前端以微信开发者工具和真机为准。
- 数据库模型变更必须新增 Alembic 迁移，生产环境不要依赖 `db.create_all()`。
- 容器入口已经自动迁移，避免与人工迁移并发执行。
