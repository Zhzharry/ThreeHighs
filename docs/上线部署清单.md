# 三高健康管理小程序上线部署清单

本文区分“代码已经具备的能力”和“必须由微信项目主体或部署人员完成的配置”。只有全部必选项完成后，才可以把环境视为真实可上线，而不是本地演示。

## 1. 当前代码已经具备

- 小程序按 `develop`、`trial`、`release` 区分后端地址。
- 普通请求和上传请求具备超时、请求追踪 ID、网络错误归一化和 401 自动重新登录。
- 趋势图具备加载中、无数据、失败重试和 7 天/30 天并发请求防串数据处理。
- 后端业务鉴权、管理员角色校验、Token 有效期与版本撤销机制。
- 微信 `code2Session`、openid/unionid 多用户绑定、登录审计和账号停用即时下线已经完成；本地仍可显式使用 mock 模式。
- 小程序首次授权页、隐私政策/用户协议原生页面、敏感健康数据单独确认和服务端版本留痕已经完成。
- 用户个人数据JSON导出已完成，只按当前登录身份导出并排除登录凭证、审计IP哈希和内部存储地址。
- 管理员密码哈希校验；明文密码仅保留给本地开发模式。
- Redis 共享限流，可支持多个 Gunicorn worker。
- MySQL 连接预检查与连接池回收。
- `/api/v1/health` 同时检查应用和数据库，成功时返回 `status=ready`。
- CORS 来源白名单、请求追踪 ID、`no-store`、`nosniff`、禁止 iframe、Referrer Policy；HTTPS 请求增加 HSTS。
- Docker 启动前自动执行 Alembic 迁移，Gunicorn 使用可配置多 worker/线程。
- MySQL、Redis 和上传目录均使用 Docker 持久卷。
- `APP_ENV=production` 时执行强制配置检查，演示密钥、SQLite、root 数据库账号、明文管理员密码、开放 CORS 或内存限流会导致启动失败。

## 2. 小程序环境地址

编辑 `frontend/miniprogram/config/index.js`：

```js
const API_ORIGINS = {
  develop: "http://127.0.0.1:5000",
  trial: "https://staging-api.example.com",
  release: "https://api.example.com"
}
```

要求：

1. `trial` 和 `release` 必须使用 HTTPS，不能使用 IP、localhost 或自签名证书。
2. 地址只填写源站，例如 `https://api.example.com`，代码会自动追加 `/api/v1`。
3. 未配置 trial/release 时，代码会明确报错并停止请求，避免体验版或正式版误连本机服务。
4. 正式上传前在微信公众平台把对应域名加入 `request` 和 `uploadFile` 合法域名。

## 3. 后端生产变量

复制 `.env.example` 为 `.env`，替换所有 `please-change`、`example.com` 和说明性占位值。`.env` 已被 `.gitignore` 排除，禁止提交到代码仓库。

重点变量：

- `APP_ENV=production`
- `DATABASE_URL`：使用独立应用数据库账号，禁止 root；密码中的特殊字符需要 URL 编码。
- `SECRET_KEY`：至少 32 位随机值，不与其他系统共用。
- `ADMIN_PASSWORD_HASH`：只保存密码哈希，不保存管理员明文密码。
- `CORS_ORIGINS`：纯微信小程序部署保持为空；只有以后单独部署受控管理后台时才填写其 HTTPS 来源，禁止使用 `*`。
- `RATELIMIT_STORAGE_URI`：生产环境使用 Redis，例如 `redis://redis:6379/0`。
- `WECHAT_LOGIN_MODE=code2session`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET`：生产必填；AppSecret 只能由密钥管理系统注入。
- `TOKEN_VERSION_REQUIRED=true`：生产必填，确保旧版或已撤销 Token 不会继续访问。
- `HEALTH_CONSENT_REQUIRED=true`：生产必填，确保未授权或已撤回用户不能继续访问敏感健康功能。
- 三个 `*_VERSION` 变量：协议内容发生实质变化时更新版本，触发用户重新确认。
- `TRUST_PROXY_COUNT`：只有部署在可信反向代理后才设为代理层数；直连后端保持 `0`。
- `GUNICORN_WORKERS`、`GUNICORN_THREADS`：结合服务器 CPU、内存和压测结果设置。

生成密钥与管理员密码哈希：

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
python -c "from werkzeug.security import generate_password_hash; print(generate_password_hash('替换为强密码'))"
```

Werkzeug 哈希包含 `$` 时，在 Compose `.env` 中使用单引号包住完整值，防止变量插值。

## 4. Docker 部署与验证

```powershell
Copy-Item .env.example .env
# 编辑 .env 并替换全部占位值
docker compose config
docker compose up -d --build mysql redis backend-api
docker compose ps
```

浏览器预览服务已退出默认运行链路。前端发布前验收统一在微信开发者工具的模拟器、自动化环境、体验版真机中完成。

健康检查：

```powershell
Invoke-RestMethod https://api.example.com/api/v1/health
```

期望业务码为 `0` 且 `data.status` 为 `ready`。还需要确认：

- MySQL 和 Redis 状态为 healthy。
- 后端日志显示 Alembic 升级成功并启动预期数量的 Gunicorn worker。
- 容器重建后用户数据、限流状态和上传文件仍存在。
- 数据库备份能够在独立测试实例恢复，不应只确认“备份文件生成成功”。

## 5. HTTPS 与网络边界

- 使用云负载均衡、API 网关或 Nginx 终止 HTTPS。
- 后端 5000、MySQL 3306 和 Redis 6379 不直接暴露公网；公网只开放 443。
- 数据库和 Redis 使用内网安全组，仅允许后端访问。
- 上传文件若需要多实例和长期保存，应从本地持久卷迁移到带私有读权限的对象存储，并使用短期签名 URL。
- 在网关层配置请求体限制、连接超时、访问日志、WAF 规则和告警。

## 6. 必须由微信项目主体/成员完成

这些事项无法通过本地代码替代：

1. 在微信公众平台确认正式 AppID、主体和开发成员权限。
2. 获取 AppSecret，并通过部署平台密钥管理注入后端；禁止写进小程序代码或 Git。
3. 把正式 AppID/AppSecret 注入已经完成的 `code2Session` 实现，并在体验版验证 openid/unionid 账户绑定策略。
4. 配置 request、uploadFile、downloadFile 等服务器合法域名。
5. 若使用订阅消息，申请消息模板并配置模板 ID。
6. 由实际主体和法律/合规负责人审查现有协议实现稿，补充真实主体、联系方式、数据保留与注销规则，并完成隐私保护指引、医疗健康类目和所需资质审核。
7. 上传体验版、邀请体验成员、提交平台审核并发布。

## 7. 发布前验收

- 使用体验版真机分别验证首次授权、Token 过期、断网恢复、弱网超时和重新登录。
- 验证撤回授权后每日记录、趋势、报告和AI健康上下文立即返回403，数据导出仍可用，重新授权后功能恢复。
- 验证不同用户之间的每日记录、报告、提醒、AI 会话完全隔离。
- 验证报告上传类型、MIME、大小、恶意文件、重复提交与删除权限。
- 验证管理员登录限流、错误密码、Token 过期、普通用户越权和审计记录。
- 对核心接口进行并发和容量测试，确认 MySQL 连接池、Gunicorn worker 和 Redis 无瓶颈。
- 配置错误率、响应时间、数据库连接、磁盘/对象存储容量和备份失败告警。
- 准备数据库迁移回滚方案、应用版本回滚方案和发布负责人。
