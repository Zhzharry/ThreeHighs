# 三高健康管理小程序需求分析清单

## 一、用户端功能

1. 健康首页
   - 展示个人健康评分、今日记录完成情况、最新异常提醒。
   - 展示血压、血糖、血脂、BMI 等核心指标摘要。
   - 提供健康档案、饮食记录、血压血糖、体检报告、AI 建议等快捷入口。

2. 健康档案管理
   - 录入和展示年龄、性别、身高、体重、BMI。
   - 维护既往病史、三高类型、用药情况、管理目标。
   - 根据基础信息建立个人健康档案。

3. 饮食记录
   - 记录每日早餐、午餐、晚餐和加餐。
   - 统计热量、糖分、脂肪、盐分等营养数据。
   - 根据三高人群饮食原则给出控糖、控压、控脂建议。

4. 血压血糖记录
   - 记录收缩压、舒张压、空腹血糖、餐后血糖。
   - 展示近期趋势、平均值、波动情况。
   - 为后端机器学习预测提供数据入口。

5. 血压血糖预测
   - 展示未来一段时间血压、血糖变化趋势。
   - 给出风险提示和生活方式建议。
   - 前端仅展示预测结果，模型计算由后端 AI 模块完成。

6. 体检报告识别
   - 支持上传图片或 PDF 格式体检报告。
   - 展示 OCR 识别进度和识别结果。
   - 自动提取血糖、血脂、肝肾功能等关键指标。

7. 异常指标预警
   - 根据医学参考范围判断偏高、偏低或异常。
   - 按低风险、中风险、高风险展示风险等级。
   - 给出复查、饮食、运动、就医等提醒。

8. 健康数据可视化
   - 展示血压、血糖、营养摄入、体重 BMI 等趋势图。
   - 后续接入 ECharts 微信小程序版。
   - 支持用户快速理解近期健康变化。

9. 个性化健康建议
   - 根据健康档案、饮食记录、血压血糖记录生成建议。
   - 支持大模型健康问答。
   - 结合 Chroma 向量库展示知识库命中来源。

## 二、管理员端功能

### 实现形态与权限边界

- 普通用户微信小程序只承载健康用户功能，不在其中设置隐藏管理员页面或特殊点击入口。
- 管理员 API 和角色边界继续保留，但本项目当前不再启动或展示 Web 管理后台，前端验收统一在微信小程序进行。正式生产若恢复运营管理端，应作为独立受控后台部署，并接入数据库管理员账号、MFA、RBAC、登录限流和操作审计，不能把管理员能力暴露给普通用户小程序。
- 用户与管理员身份必须由后端 Token 和权限声明区分，所有 `/admin/*` 接口执行后端鉴权；前端是否显示入口不能作为安全边界。
- 如果确需移动运营端，应建立独立 AppID 的管理小程序或企业微信应用，复用同一套后端 RBAC，不与健康用户小程序混合发布。

1. 用户管理
   - 查看用户列表、三高类型、风险状态和活跃情况。

2. 健康数据维护
   - 维护用户血压、血糖、血脂、BMI 等健康数据。

3. 饮食数据维护
   - 维护食物营养信息，包括热量、糖分、脂肪、盐分。
   - 支持勾选当前页数据后批量删除，并进行二次确认。

4. 报告审核
   - 查看 OCR 识别后的体检报告。
   - 对异常识别或低置信度指标进行人工审核。
   - 支持批量通过或批量驳回选中报告。

5. 系统公告管理
   - 发布饮食提醒、复查通知、系统维护公告。
   - 支持批量发布和批量转为草稿。

## 三、前后端分离边界

- 小程序前端负责页面展示、用户交互、表单录入和图表展示。
- Flask 后端负责 RESTful API、业务逻辑、数据库读写和管理员数据维护。
- OCR、预测模型、大模型问答、向量检索均封装为后端 API。
- 前后端通过 JSON 进行数据交互。

## 四、当前三大主页面对应关系

| 功能模块 | 小程序页面 | 当前实现 |
| --- | --- | --- |

| AI | `frontend/miniprogram/pages/ai/index` | 健康问答、今日建议、知识库命中展示 |
